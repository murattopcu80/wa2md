# wa2md

[![CI](../../actions/workflows/ci.yml/badge.svg)](../../actions/workflows/ci.yml) ![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg) ![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)

> **Unofficial tool.** wa2md is an independent open-source project. It is not affiliated with, endorsed by or connected to WhatsApp or Meta. "WhatsApp" is used here only to name the chat format and the web page that the tool reads.

> **Read the ENTIRE output before you share it.** Anonymization here is heuristic: it removes direct identifiers and misses things (see "What this tool does not find automatically"). The review file is a help, not a guarantee. **Pictures, videos and voice notes are copied as they are and are NOT anonymized** (faces, ID documents, bank cards, screenshots with names): use `--no-media` before sharing.

Converts WhatsApp chats (one-to-one or group) to Markdown files with the photos embedded, and anonymizes them by default. There are two input paths; both use the same Markdown writer (`wa2md.write_chat`), so the output format is the same.

1. **WhatsApp Web (recommended):** no export step on the phone. A JavaScript collector (`wa_collect.js`) runs in a logged-in WhatsApp Web tab; `wa_web.py import` turns its result into Markdown.
2. **Phone export (alternative):** converts WhatsApp's own "Export chat" zip. See below.

Output: `<out>/<chat-name>/<chat-name>.md` and `<out>/<chat-name>/media/`. The output is anonymized by default: names are replaced by `Sohbet-N` / `Kişi N` (Turkish for "Chat-N" / "Person N"; see "Anonymization"; turn it off with `--no-anonymize`). The folders with real names in the examples below are produced with `--no-anonymize`. **Media is copied by default, also in anonymous mode, and it is not anonymized**; add `--no-media` for output that you will share (a console warning line reminds you whenever media was copied).

The tool uses only the Python standard library. It was written first for Turkish chats; the language support is described honestly in "Language support" below, and full English support is being built (see [issue #2](../../issues/2)).

## Quick start

```
python wa2md.py "C:\Users\user\Downloads\WhatsApp Chat with Ali Veli.zip" --out C:\Users\user\wa-out
```

The output is anonymized by default. You need Python 3.9 or later and nothing else. For the WhatsApp Web path see section 1, for the phone export see section 2.

**Before you share anything:** pictures, videos and voice notes are copied into `media/` **as they are and are NOT anonymized** (faces, ID documents, bank cards, screenshots with names). Run with `--no-media` to leave them out, and read the entire Markdown output yourself:

```
python wa2md.py "C:\Users\user\Downloads\WhatsApp Chat with Ali Veli.zip" --out C:\Users\user\wa-out --no-media
```

## Limitations and responsible use

- **Detection is best-effort.** Anonymization here is heuristic (dictionaries, patterns and context rules). It removes direct identifiers; it does not make a chat anonymous in the legal sense, and no anonymizer finds everything. Names that are not in the dictionaries, unusual spellings, nicknames, places, job titles, and details that identify a person only in combination will be missed, and ordinary words are sometimes masked by mistake.
- **Read the entire output before you share it.** The review file lists suspicious words that stayed in the text; it is a help, not a guarantee.
- **Media is not anonymized.** Photos, videos and voice notes are copied as they are (faces, documents, screenshots); use `--no-media` for anything you share.
- **Use it only on chats you are entitled to process.** Make sure that you and the other participants are fine with the conversion, and keep the originals, the raw `wa-bundle-*.json` files and the output as safe as the original chat.
- **Report misses with invented examples only.** See [CONTRIBUTING.md](CONTRIBUTING.md); a way to leave personal data unmasked contrary to the documented behaviour is a security problem ([SECURITY.md](SECURITY.md)).

## Install (optional)

`python wa2md.py ...` works straight from a checkout. To get commands on your PATH instead, install from the checkout (Python 3.9 or later, no third-party dependency):

```
pip install .
wa2md --help        # same as python wa2md.py
wa2md-web --help    # same as python wa_web.py (WhatsApp Web helper)
```

The dictionaries (`adlar/`) and the collector (`wa2md_assets/wa_collect.js`) are installed with it and found at run time. The experimental direct Chrome connection (`wa2md-web list` / `export`) needs the optional extra: `pip install ".[browser]"` (Playwright). Nothing is published to PyPI.

## Language support

The project is going global: **English is the primary language and Turkish is a supported language** (decision recorded in [issue #1](../../issues/1); the Turkish README is [README.tr.md](README.tr.md)). **Full English support is being implemented** as language packs ([issue #2](../../issues/2)); Turkish-only detection is not the intended end state. This section describes the state of this branch exactly, what is ready and what is not:

- **Command line, help and console messages:** English by default; Turkish with `--lang tr` or `WA2MD_LANG=tr`. Every option has an English primary name; the old Turkish names are accepted aliases with identical behaviour (table below).
- **Language-independent today** (verified in the code and in trial runs on invented English, Cyrillic, Arabic and Chinese chats):
  - sender names from the export (in any script) and their occurrences in message text, including `@mentions`;
  - people in system lines, in English and Turkish (`X added Y`, `X left`, `X, Y'yi ekledi`, ...);
  - e-mail addresses; social profile, WhatsApp channel, invite and `wa.me` links;
  - international phone numbers that start with `+`, and numbers with the `00` prefix;
  - password keywords (`password`, `pin`, `token`, `api key`, `şifre`, `parola`, ...) and known secret formats (`ghp_...`, `sk-...`, JWT, long hex/base64, `Bearer ...`);
  - one-time codes tied to the word `OTP`;
  - the parser reads Android and iOS export formats, 24-hour and 12-hour clocks (AM/PM and the Turkish `ÖÖ/ÖS`), and recognizes English and Turkish attachment and media-omitted markers.
- **Turkish-specific today** (does not work, or behaves wrongly, in English or other-language chats):
  - given-name and surname dictionaries (`adlar/tr-*.txt`): English names are found only when they happen to be in the Turkish dictionary (in a trial run `John` and `Henry` were masked; `Sarah`, `Mark`, `Mary` and `Wendell` were not); the reverse also happens: Turkish names that are ordinary English words are masked even in lower case (`hare`, `violet`, `lee` and `jack` in `a hare ran past the violet flowers`);
  - honorifics (`bey`, `hanım`, `abi`, `Sayın`, ...; `Mr`, `Mrs`, `Dr` are not recognized);
  - contact context words (`irtibat`, `tel`, `yetkili`, ...; `contact`, `call`, `reach` are not recognized);
  - trade names (sector words such as `nakliyat` and `lojistik` and legal forms such as `Ltd. Şti.`, `A.Ş.`; the English `Ltd.` also triggers the company rule);
  - the place list (81 provinces, 903 districts);
  - Turkish suffix handling and case folding (İ/I/ı/i);
  - IBAN (only `TR`), Turkish national ID number, Turkish licence plates;
  - one-time code detection through the words `kod/doğrulama/onay` (`code` and `verification` are not recognized);
  - phone patterns are written for Turkish shapes: a foreign number written without `+` or `00` is masked only if it happens to fit a Turkish shape (in a trial run `020 7946 0958` was masked; `415-555-0132`, `07700 900123` and `0151 23456789` were not);
  - system lines and attachment/omitted markers of languages other than English and Turkish, and export formats with an ISO date (`2026-11-14`), a year-first date (`2026/11/14`), a hyphen-separated date or a French `à` (these lines are not parsed).
- **Output labels are Turkish until phase 2** (`Sohbet-N`, `Kişi N`, `[telefon]`, `[firma]`, `[yol]`, `[e-posta]`, `[kullanıcı]`, `[parola]`, `[kod]`, the headings `Katılımcılar:` (participants), `Mesaj sayısı:` (message count), `Tarih aralığı:` (date range), and notes such as `_Yönlendirilmiş mesaj_` (forwarded message)). The anonymizer's own patterns embed this label text, so translating the labels is an engine change, not a text change; it comes with the language packs ([issue #2](../../issues/2)).

The console lines quoted in this README are the English messages.

## 1. WhatsApp Web path (console path — the path that works today)

> **Important note (WhatsApp Web path):** This path only reads your own chats, in a browser tab that you logged in to yourself, and sends no data anywhere. Even so, automated collection from WhatsApp Web can conflict with WhatsApp's terms of service. The recommended path is WhatsApp's official "Export chat" feature (section 2 below). Using the Web path is entirely at your own responsibility. Files that belong to this path: `wa_web.py`, `wa_collect.js`, `tests/test_wa_web.py`, `tests/test_browser_smoke.py` and `tests/fixtures/web/`.

The collection logic (finding the chat through the search box, scrolling to older messages, message parsing, photo blobs) is in a single file: `wa2md_assets/wa_collect.js`. No external connection to Chrome is needed; the code runs in your open WhatsApp Web tab.

### Setup (once)

Python 3 is enough (no extra package for the console path). Only for the experimental CDP path and the browser tests: `python -m venv .venv` and `.venv\Scripts\pip install -r requirements.txt` (or `pip install ".[browser]"`).

### Steps

1. Generate the ready-made JS (it is also copied to the clipboard):

   ```
   python wa_web.py snippet --chats "Ali Veli,Sample Group"
   python wa_web.py snippet --chats "Ali Veli" --from 2026-01-01 --to 2026-11-14 --max-messages 500 --no-media
   ```

2. In the logged-in `web.whatsapp.com` tab in Chrome open **F12 → Console**, paste the code, press Enter. The first time, Chrome asks you to type `allow pasting` for safety: type it, press Enter, then paste again.
3. Watch the `[wa] ...` progress lines in the console (do not close the tab, do not put the computer to sleep; scrolling is done at human speed). When it finishes, the bundle(s) try to download automatically: `wa-bundle-<chat>-<session>-001.json` appears in your **Downloads** folder. Chrome may block the download from the page (click **Allow** in the "download multiple files" prompt in the address bar) or the file may not download at all; click the **link in the green box** at the top right of the page. If that does not download either, press the **"Download in a new tab (backup)"** button in the same box: the file downloads with a random name (a GUID, no extension); `import` recognizes it from the header inside it, not from its name (pass the file directly as a path). Small chats are a single file; large ones are split into numbered parts of about 40 MB (`-001`, `-002`, ...).
4. Convert the bundles to Markdown (a folder or files can be given; all parts of the same chat are read together, and it tells you if a part is missing):

   ```
   python wa_web.py import C:\Users\user\Downloads --out C:\Users\user\wa-out
   python wa_web.py import wa-bundle-ali-veli-abc123-001.json wa-bundle-ali-veli-abc123-002.json --out C:\Users\user\wa-out
   ```

   A summary line is written for every chat: `[Name] N messages, M media copied, K media missing -> path`. The bundles contain private chat data: delete the `wa-bundle-*.json` files when you are done. `import` scans a folder as it is: if old bundles are still there, it converts them too.

Options: `--from` / `--to` date range, `--max-messages N` newest N messages, `--no-media` do not download media, `--older-from-phone` click the "Click here to get older messages from your phone" button at the start of the chat (default: do not click; the phone must be on). `import` also accepts `--from/--to/--max-messages`; `import` and `export` also accept the same anonymization options as `wa2md.py` (`--extra-names`, `--review-dir`, `--no-dictionary`) with the same meaning.

### Experimental: connecting directly to Chrome (`list` / `export`) — connection not verified

```
.venv\Scripts\python wa_web.py list
.venv\Scripts\python wa_web.py export --chats "Ali Veli" --out C:\Users\user\wa-out
```

This runs the same `wa_collect.js` by attaching to a running Chrome with Playwright and hands the bundles straight to the `import` code. On `chrome://inspect/#remote-debugging` the box "Allow remote debugging for this browser instance" must be checked, and **Allow** must be clicked in the permission dialog that appears on the first connection. **A connection to a real Chrome has not been verified**: in the maintainer's test environment, with Chrome 157, the endpoint did not answer the WebSocket handshake (three attempts timed out). That the script works with its own temporary Chrome is shown by the tests. If it cannot connect, the command reports an error and recommends the console path.

### Read-only, but the read receipt goes out

The collector writes nothing, sends nothing, reacts to nothing, deletes, archives or mutes nothing, and changes no setting. It only types into the chat search box (and clears it afterwards), opens the chat, scrolls, opens and closes the photo/GIF preview (media viewer), and expands "Read more" on long text. However, **opening a chat marks that chat's messages as "read"** (the other side gets the blue tick). This is inherent to this path and accepted. Texts inside chats are treated as untrusted data; instructions inside them are ignored.

### Limits

- Photos are taken from the full-size image already loaded in the chat (WhatsApp Web already holds a decoded blob); if it is not loaded (a size such as "136 kB" and a download arrow are shown on it), that download arrow is clicked (it arrives in about 1 s); old photos that do not arrive with this click (WhatsApp may have deleted them from the server) are not tried again and stay as `_(dosya eksik: ...)_` ("file missing"). In other cases the media viewer is opened and closed. Every photo in an album is a separate file (`...-1.jpg`, `...-2.jpg`). GIFs are saved as `.mp4`. A photo that cannot be obtained becomes `_(dosya eksik: ...)_` in the Markdown. Video and audio are **not verified** (there was no example in this chat); documents are not downloaded (it would trigger a browser download): a placeholder line (`_belge indirilemedi: rapor.pdf_`, "document could not be downloaded") is written.
- Forwarded messages are written with the note `_Yönlendirilmiş mesaj_` ("forwarded message"). Reactions (emoji) and link preview cards are not written (the link text in the message is written). Bold/italic markers are not kept.
- WhatsApp Web shows only messages synced with the phone. Older messages are on the phone; the collector reports this with a note and clicks the button only with `--older-from-phone`.
- If a day heading is "TODAY/YESTERDAY/weekday" it is resolved against the collection date. The time of unstamped (media-only) messages comes from the message footer, and the date from the day heading or from neighbouring messages; the sender name comes from the label on screen, and for an outgoing message from your own name.
- WhatsApp changes its interface often. All selectors are in the `SEL` table at the top of `wa_collect.js`; each line says whether it was verified by observation in the WhatsApp Web interface (`[V]`) or is unverified / a guess (`[U]`). If something breaks, look at `SEL` first.

## 2. Export from the phone (alternative)

1. Open the chat in WhatsApp.
2. Android: top right **⋮** → **More** → **Export chat**. iOS: tap the contact/group name at the top → **Export Chat**.
3. Choose **Include media**.
4. Move the resulting zip file to the computer (e-mail, Drive, cable, etc.).

Note: WhatsApp limits the export. About 10,000 of the latest messages with media, about 40,000 without media, are exported. Older messages are not in the file.

```
python wa2md.py <input> [<input>...] --out <folder> [--only "name1,name2"] [--from YYYY-MM-DD] [--to YYYY-MM-DD] [--name NAME]
               [--no-media] [--copy-documents] [--extra-names "First Last,Name2" | --extra-names @names.txt]
               [--review-dir FOLDER] [--no-dictionary] [--no-anonymize] [--lang en|tr]
```

Input: a zip file, an extracted folder, or a folder that contains several zips. Only Python 3 is needed (no extra package).

```
python wa2md.py "C:\Users\user\Downloads\WhatsApp Chat with Ali Veli.zip" --out C:\Users\user\wa-out
python wa2md.py C:\Users\user\exports --out C:\Users\user\wa-out --only "ali,veli" --from 2026-01-01 --to 2026-11-14
```

Input files are never touched; on a re-run only its own `.md` file is written and media of the same size is skipped.

## Anonymization (default ON)

Both paths (`wa2md.py`, `wa_web.py import` / `export`) **anonymize** the output by default ("anonymization" here means: removal of direct identifiers). Turn it off with `--no-anonymize`; when it is off the output is written with real names as before.

What the default mode does (only in the Python writer; the collector in the browser is unchanged, and the raw `wa-bundle-*.json` bundles contain real names, so delete them when you are done):

- Senders become `Kişi 1`, `Kişi 2`, ... (in order of first appearance in the chat, your own messages included). The participant list and quote authors are written with the same label.
- **Every person in system lines** also gets a `Kişi N` (even if they never wrote a message) and is masked with that label throughout the chat: added/removed, joined via invite link, left, created the group, changed subject/icon/description, changed number, security code changed; English (`X added Y and Z`, `X joined using this group's invite link`, `X left`, `X changed to +90…`) and Turkish native (`X, Y'yi ekledi`, `X … katıldı`, `X ayrıldı`, `X grubu oluşturdu`). People who appear as a number also get a label; a person who changes their number gets the same label for the old and the new number. A form of a name with emoji/symbols removed (`Ali 🚒` → `Ali`) is looked up with the same label. In an iOS export the system lines arrive in the sender position with the group name (`[..] Group Name: Ali added Veli`): this is decided only in a group chat and **line by line**; a line that comes from the group name becomes a system line if it is an event that exists only in groups (group created, added/removed, joined via invite link, subject/icon/description changed, admin), if its person is a name-shaped joined/left line (`Jorvik Plimm left`) or if it is a person-less notice (encryption, security code); if the group name writes only these, it does not become a participant. A member saved under the same name as the group (`Annem`, Turkish for "my mother") keeps writing real messages, and the people in event lines are still masked. In a one-to-one chat the other person's messages are never touched (`Kardeşim de katıldı.` ("My sibling joined too.") stays a message, the person is a participant). The Turkish native patterns were tested with invented examples; they were not verified against a real Turkish export.
- The chat title, folder and `.md` name become `Sohbet-N`; the chat name is always masked in the title, in system lines (`created group "…"`, the quoted old/new name in a subject change) and in file names. **In message text** it is masked only in these cases: a one-to-one chat (the title is the other person's name; it becomes `Kişi N` like the person, even if they wrote nothing in the date range) or a title that contains a person name (a dictionary name, a participant name part, `… Ailesi` ("family"); for example "Plimm Ailesi" → `Sohbet-N` in the text). In that case only the **name-like** words of the title are masked on their own (a participant name part, a dictionary first name/surname with no ordinary-word meaning, the word before `Ailesi`): if the group is "Selin Doğum Günü" ("Selin Birthday"), "Selin" and the full title are masked, and "doğum günü pastası" ("birthday cake") stays as it is. The words of a group title that is an institution name or a generic phrase stay as they are in the text (if the group name is "Örnek Satranç Kulübü" ("Sample Chess Club"), "satranç eğitimi" ("chess training") and "Örnek Satranç Kulübü toplantısı" ("Sample Chess Club meeting") do not change). Whether a chat is one-to-one or a group is decided **from the export itself**, looking at the whole file before the `--from/--to` filter, not from the title words: it is a group if there are at least 2 distinct senders that are not the chat name (in a one-to-one chat the senders are the other person = the chat name, and the person who exported) or if there is an event line that exists only in groups. So a name of the form `… Apartman` ("… Apartment building") or a 4-word name stays one-to-one (its name is masked in the text); a 2-person chat whose chat name is not a sender ("Kuzey Yıldızı", "North Star") is a group. N is the position in that run (the order of `--chats` / of the given inputs). If the same inputs are run again in the same order, the same folders are overwritten. Output folders are **positional**: `Sohbet-1` can be a different chat in a different run, and if `<out>/Sohbet-N` exists the `.md` is overwritten and media is added. If you are unsure, use a new `--out` for every run. `--name` (`wa2md.py` only) uses the label you give instead of `Sohbet-N`.
- In message text, participant names (senders and people in system lines; full name, case-insensitive including the Turkish İ/I/ı/i, whole word, `@Name` mentions) become the corresponding `Kişi N` / `Sohbet-N` (in a one-to-one chat the chat name is that person's label). `@Name` mentions of non-participants (a dictionary name or a capitalized word) also become `Kişi N`; `@` followed by digits is masked like a phone; a lone username that contains `.` or `_` (`@xandor.plimm`, `@xandor_plimm`) becomes `[kullanıcı]` ("user"). Suffix forms are kept (`Naime'ye`, `NAİME’DEN` → `Kişi 1'ye`, `Kişi 1'DEN`; these are Turkish case suffixes); a first name alone (for example "Naime" for "Naime Tan") is also masked if it is not ambiguous among the participants. Phone numbers (Turkish mobile/landline, `0850`/`0800` lines, `+90`, `0090`, `+<8-15 digits>`; including those inside a wa.me link) become `[telefon]` ("phone"); digits in Unicode decorated forms (full-width `０５００`, mathematical bold/double-struck `𝟎𝟓𝟎𝟎`, keycap `0️⃣`, Arabic-Indic `٠٥٠٠`) count as ASCII. A Turkish number with a `0`/`90` prefix is masked as a whole digit sequence regardless of grouping and separator (`0500-00-0000`, `0500 0000000`, `0500/000 00 00`, `0500 - 000 00 00`, `0500,000,00,00`, `0500_000_00_00`, `0500·000·00·00`, full-width/Unicode dash `０５００－０００…`, NBSP/thin space, `(0500) 000 00 00`, `(0500)  -  000  -  00  -  00`, `0500 ... 000 ... 00 ... 00`, with spaces between separators `0500 - - 000 00 00`, `0500 . . 000 00 00`), also when glued to a word (`Tel0500…` (`Tel` = "phone"), `ara0500…` (`ara` = "call")); a mobile number without the prefix only when glued to a contact word (`TEL500 000 00 00`, `GSM5000000000`). Direction marks and the BOM are dropped. Zero-width characters (zero-width space, word joiner, ZWJ, ZWNJ) and the soft hyphen stay in the text as before this change and are a word boundary in name matching: a name with these characters inside it or between names is outside the scope of this tool (a known limit). The one exception is the phone: a zero-width character or soft hyphen between the digits (and separators) of a number does not stop the masking (`0532`, zero-width space, `111 22 33` → `[telefon]`); the character after the number does not enter the mask. Emoji sequences, flags, keycaps, skin tones, Persian and Devanagari text are not damaged. Comma, underscore and middle dot are separators only in phone-shaped grouping: a sequence made only of two-digit groups (`05,06,07,08,09 Kasım` ("November"), `Gün 05-06-07-08-09` ("Day"), `Saatler 00.30, 01.30, 02.30` ("Hours"), `05,10,15,20,25 ton`) and thousands grouping (`1,500,000 TL`) are not phones; a foreign number `+49 …` and `0049 151 …` (with a separator after the country code; `0012345678` without separators counts as a reference number and is not masked); a repeated mobile prefix before the sequence or a separate exchange/country prefix (`0500 0500 000 00 00`, `0 - 500…`, `00 500…`) does not stay exposed (earlier, a fixed 3-3-2-2 pattern matched only the end of a long sequence and left the prefix); a second number joined by a hyphen (`…00-0500 …`) is masked too. Time + abbreviation + phone (`08:30 TEL 0500 …`) is not taken for a plate; e-mails become `[e-posta]` ("e-mail"), IBAN (`TR` + 24 digits) `[iban]`, Turkish national ID number (an 11-digit number standing alone) `[tckn]`, licence plates (`34 ABC 123`, `06AB1234`) `[plaka]` ("plate"). In social profile links (instagram, facebook, x/twitter, tiktok, youtube, linkedin `in/`, t.me, threads) the username, in a WhatsApp channel link (`whatsapp.com/channel/<id>`, `web.whatsapp.com/channel/…`, including the URL-encoded `%2Fchannel%2F<id>` in a redirect link) the channel id, and in a group invite link (`chat.whatsapp.com/<code>`) the invite code becomes `[kullanıcı]`; the number in a `wa.me/<number>` link becomes `[telefon]`; the domain name and post paths (`instagram.com/p/…`) stay. Dates, times, prices, amounts (`550+KDV` (`KDV` = VAT), `25 ton`, `10 teker` ("10 wheels")) and short numbers are kept; other 11-digit numbers or a code that fits the plate shape (`34 AB 1234`) can be masked by mistake.
- **Names of non-participants, found automatically without a list:** the built-in offline name dictionary (`adlar/tr-adlar.txt` 2190 names, `adlar/tr-soyadlar.txt` 4819 surnames; source Wikidata, licence CC0 1.0, retrieved 2026-11-14, queries at the top of the file) and honorifics. The same loader also reads the place list: `adlar/tr-yerler.txt` (the 81 provinces and 903 districts of Turkey, 984 names in total, 15.8 KB; source Wikidata, licence CC0 1.0, retrieved 2026-11-15; query, cleaning steps and counts at the top of the file). Province names are listing vocabulary (not taken for a person or company name); a district name that is also in the first-name or surname dictionary (`Fatih`, `Kartal`, `Bozkurt`) is ambiguous and does not enter the place rules. **If the dictionary files (the place list included) are missing,** an anonymized run fails (exit code 2); you accept running without them explicitly with `--no-dictionary`, and the summary prints `WARNING: name dictionary MISSING`. The rules: a name that has no ordinary-word meaning (Mehmet, Naime) is masked in every form (lower case, sentence start, with a suffix: `mehmetle` ("with Mehmet")); a name that is also an ordinary word (`adlar/sozcuk-adlar.txt`, ~450 words: deniz ("sea"), umut ("hope"), barış ("peace"), kaya ("rock"), bora, poyraz ("north wind"), selim, ramazan, fırat …; sources at the top of the file: Wikidata lexemes and Turkish place/river names (CC0) and a hand-reviewed list) is masked only through context: a capital letter in mid-sentence (`dün Deniz aradı` ("Deniz called yesterday")), a proper-noun apostrophe suffix (`Umut'a`, also in lower case: `bora'ya`), a form of address (`Deniz abi`), a capitalized surname after it (`Deniz Kaya`) or a known name next to it. An ambiguous word in lower case or at the start of a sentence, and a title form (`Temel Satranç Eğitimi` ("Basic Chess Training"), `Türk Medeni Kanunu` ("Turkish Civil Code")), stays as it is but is counted. The place/institution exception is narrow and applies **only to dictionary names that are not participants**: a name plus an institution word (`Üniversitesi, Lisesi, Hastanesi, Köprüsü, Caddesi, Sokağı, Bulvarı, Mahallesi, Camii, Parkı, Stadı …` (university, high school, hospital, bridge, avenue, street, boulevard, neighbourhood, mosque, park, stadium)) must be capitalized, with only a single space between, a single proper-noun phrase: the name right before the institution word (`Mimar Sinan Üniversitesi`, `Atatürk Caddesi`) or a chain with words in between (`Fatih Sultan Mehmet Köprüsü`); also a name after `Hz.` (an honorific for religious figures). A participant's name or name part never stays exposed through any exception (`Kenan Ankara Hastanesinde` ("in Kenan Ankara Hospital"), `Kenan müzesinde` ("in Kenan's museum"), `Hz. Kenan` → `Kişi N`). A case that cannot be decided (`Zeynep Gazi Üniversitesi'ni kazandı` ("Zeynep got into Gazi University"), a lower-case institution word, a name with a suffix) is masked and counted in the summary as `place/institution unclear`. If a different surname is added to a known name (`Kenan Karakoç` when `Kenan Er` is a participant) it is a separate person with a separate `Kişi N`; a dictionary name before a participant's full name is not merged with it (`Mimar Mert Er` and `Selin Mert Er Lisesi` when `Mert Er` is a participant: the participant's full name gets their own label, the name in front becomes a separate person by the rules or stays; the surname is never left exposed); if a single name found through the dictionary is later mentioned with its surname (`Ahmet`, `Ahmet Yıldırım`), the label stays the same. Surname + form of address (`Karakoç Hoca`, `Şimşek abi`) is masked at the start of a line too; so is a capitalized name after `Sayın`/`Sn.` ("Dear/Mr./Ms.") (except `Sayın Yetkili` ("Dear Official"), `Sayın Üyelerimiz` ("Dear members")). Month and day names (`12 Ekim'de` ("on 12 October")) are not masked. Form of address: a capitalized word before `Bey, Hanım, abi, abla, hocam, hoca, başkan(ım), kardeş(im), amca, teyze, usta` (Mr., Mrs., elder brother, elder sister, teacher, president, sibling, uncle, aunt, master; and their suffixed forms) is masked even if it is not in the dictionary; constructions such as `Tamam abi` ("OK bro"), `Selam hocam` ("Hello teacher"), `Sayın Başkan` ("Dear President"), `Dernek Başkanı` ("Association President") are left alone. A word that is not in the dictionary, at the start of a sentence before a form of address, is not masked; it is written to the review file.
- **A name list is not needed in a normal run.** `--extra-names "First Last,Nickname"` (or `--extra-names @file`, one name per line) is only a backup: you give names that you saw in the review file are real, or that are not in the dictionary; they are masked in every form like a participant. The mapping is still not written anywhere.
- **Freight listings** (in open freight groups, listings are signed with a name, a company name and a phone; the rules run on the same `Anonymizer` path and have been tested with invented listings; every review case is one row in the `tests/test_nakliye_karar_tablosu.py` table). Two principles: where things cannot be told apart, it masks (over-masking is accepted), and nothing that the previous version masked is unmasked (the only exception: the proven route place below). Whatever the order of the messages, later evidence only strengthens what is known: a name known only through contact evidence spreads with the same label in every form once evidence from the previous version (`Sayın`, form of address, `@`, dictionary name) arrives. `InteractionMainParity.test_never_masks_less_than_main` in `tests/test_nakliye_karar_tablosu.py` tests this: in 300 invented, interaction-heavy chats, every word the previous version masked is also masked in the branch. *Listing marker:* a message is a listing if it contains a phone or a contact word **as a field** (followed by `:`, `-`, `.`; also with a label such as `Tel No:`, `Yetkili Kişi:`) ; since a listing is a multi-line message, the marker can be on any line of the message.
  - *Name in contact context:* names around a contact word (`irtibat`, `irt.`, `iletişim`, `ilt.`, `tel`, `tlf`, `telefon`, `gsm`, `cep`, `yetkili`, `sorumlu`, `whatsapp`, `wp` and the misspellings `whatsap`, `watsap`, `vatsap`, `wtsp`, `wsp`, the channel `telegram`; case-insensitive; none is learned as a name; these mean contact/liaison, phone, mobile, authorized person, responsible person) and around a phone are separated by strength of evidence. **Strong evidence:** after a delimited field (`İrtibat: First Last`, `İRTİBAT İÇİN: First Last` ("contact for"), `Tel (Ofis): First Last`, `İRTİBAT ⇒ FIRST LAST`, `Yetkili Adı Soyadı: First Last` ("authorized person's first and last name"); the field label stays readable), glued to a phone on the same line (`0500… First Last`, `First Last 0500…`, also a single word: `Last 0500…`; a phone or pointer emoji, an arrow, `|`, `*` may be in between: `First Last 📞 0500…`, `0500… 👉 First Last`), two-three words, or a name in the list, before such a field (`First Last Tel: 0500…`, `FIRST LAST GSM 0500…`), or a dictionary name + a surname in the list. Strong evidence gives the person **a single label**, valid everywhere in the chat (in the same message `First Last bey yoksa…` ("if Mr. First Last is not there…"), in another message `First Last yükü aldı mı?` ("did First Last take the load?") → the same `Kişi N`; the same first name with a different surname is a different person). If a part of the name is in the name dictionary, the other parts get the same label too; a part not in the dictionary only in its capitalized form (after `İrtibat: First Last`, `Last bey aradı` ("Mr. Last called") → `Kişi N bey aradı`). If a part is a participant name part, the full phrase spreads in every form as in the previous version (`first last geldi` ("First Last came")); single parts as below. If no part is in the name dictionary or in a participant name, only the full phrase spreads, and only in its capitalized form: there are many ordinary words in the surname list (`Tel: Sıcak Çorba 0500…` ("Hot Soup") then `sıcak çorba içtik` ("we had hot soup"), `Sıcak hava var` ("it's hot"), `çorba soğudu` ("the soup got cold"); `İrtibat: Mavi Kapak …` ("Blue Lid") then `Mavi araba geldi` ("the blue car came") do not change). A single part gets the label of the full name only right before a form of address (also at the start of a line) or right after `Sayın` (`Last bey aradı`, `First hanım yazdı` ("Mrs. First wrote"), `Sayın Last` → `Kişi N`); if a part is shared by two different names, the label is `Kişi ?`. A phrase ending in a unit word is not a person (`Muhasebe Birimi` ("Accounting Unit"), `Satış Departmanı` ("Sales Department"), `Gündüz Ekibi` ("Day Team"); `birimi`, `departmanı`, `ekibi`, `bölümü`, `müdürlüğü`, `şubesi`, `ofisi`, `servisi`, `deposu`, `merkezi`, `grubu`… (unit, department, team, section, directorate, branch, office, service, depot, centre, group)). An ordinary word after a name that has no ordinary-word meaning in the dictionary is not counted as a surname (`First Bekliyor 0500…` ("First is waiting") → `Kişi N Bekliyor [telefon]`). A lower-case name after the field is also taken as a whole if its first word is a dictionary name (`İrtibat: first last 0500…`). A strong finding that does not pass the ordinary-word test (inflection/possessive suffix, dictionary, filler or place word: `İrtibat: Proje Masası 0500…` ("Project Desk")) is masked only at that place. **Weak evidence** is masked only at that place and only if it passes the ordinary-word test: the single unknown word before a field with a phone (`Last Tel: 0500…`, `LAST GSM 0500…`) and a name next to a contact word without a delimiter (`FIRST LAST İRTİBAT`, `irtibat First Last`); if the line has no phone, the latter is taken only in a message with a listing marker (phone on a lower line), and, if a single word, only if it is a first name or surname in the list (`İletişim Kurun Lütfen` ("Please get in touch") is not a name). A place name or dictionary word before the phone or field is not a name (`Gebze 0500…`, `Ofis Tel: 0500…` ("Office"), `ACİL YÜK 0500…` ("urgent load")). Filler and field-label words (`no`, `için`, `adı`, `soyadı`, `numara…`, `telefon…`, `sadece`, `lütfen`, `arayınız`, `hafta içi`, `servis`, `bilgileri`, and before the phone `büro`, `ofis`, `faks`, `dahili`, `hat`, `mobil`, `sabit`… (no., for, name, surname, number, phone, only, please, call, weekdays, service, details, bureau, office, fax, extension, line, mobile, fixed)) are never taken as a name; a candidate after such a channel label that follows the phone is taken as a name only if one part is in the name dictionary, and it is masked only at that place, not spread through the chat; a label word that is also in the name dictionary is the first part of the name when it has no `:` (`0500… Sabit Soyad` → `[telefon] Kişi N`; `Sabit: 0500…`, `Sabit hat 0500…`, `0500… Sabit Hat` stay as they are) (`0500… Ofis: First Last` → `[telefon] Ofis: Kişi N`; `0500… Mobil Uygulama` ("Mobile App"), `0500… Ofis Saatleri` ("Office Hours") stay as they are) (`WhatsApp Web açılmıyor` ("WhatsApp Web does not open"), `Telefon Numarası` ("Phone Number"), `Yetkili Servis` ("Authorized Service"), `Cep Telefonu Faturası` ("Mobile Phone Bill"), `İletişim Bilgileri` ("Contact Details"), `Hafta İçi Arayınız 0500…` ("Call on weekdays")). A name that is also an ordinary word (`Barış`) is not left to the review file in this context, it is masked.
  - *Signature line:* a name-shaped line next to a listing-marker line in the same message (optional emoji/punctuation, then 2-3 capitalized words, the first a dictionary name: `🪪 First Last`) is a signature. If the surname is in the list it is strong evidence (one label for the whole chat); if not, it is **weak evidence**: only the word in the surname position is masked if it passes the ordinary-word test, and in the rest of the chat only as the full phrase, in its capitalized form (`First Last aradı mı` ("did First Last call"), `FIRST LAST`) with the same label; its single parts do not spread (before a form of address or after `Sayın` they again get the same label). `Sevgi Saygılarımla` ("With kind regards"), `Umut Ediyoruz` ("We hope"), `Can Dostlar` ("Dear friends"), `Nur Ola` ("Let there be light") are not signatures and do not spread to other lines.
  - *Surname in a listing:* in a message with a listing marker, or on the same line as a strong sector word (`… NAKLİYAT ALİCAN SOYADI` → `[firma] NAKLİYAT Kişi N`), a word that is not in the list after a dictionary name with no ordinary-word meaning, in the surname position (end of line; before a phone, contact word or delimiter), is a surname by weak evidence: only at that place and only if it passes the ordinary-word test. A verb or ordinary word is not a surname; only the first name is masked (`Hasan Gelsin` ("Hasan, let it come"), `hasan gelsin dedi patron` ("the boss said let Hasan come"), `Mehmet Yazıyor:` ("Mehmet is writing:") → `Kişi N Gelsin`, `Kişi N gelsin dedi patron`, `Kişi N Yazıyor:`); listing, sector, legal-form and filler words are not surnames.
  - *Name part glued to a participant label:* the other name part that a participant whose displayed name is a single part writes in a listing heading/signature joins the label: `First+Kişi N`, `First + Kişi N` and a signature line `First Kişi N` always; with a space inside a sentence (`… First Kişi N …`, `Kişi N First`) only in a message with a listing marker. Without a listing marker an ordinary word does not join (`dün Review Kişi N yaptı` ("yesterday Review Kişi N did")); an ordinary word separated by a space at the start of a sentence (`Dün Kişi N aradı` ("Yesterday Kişi N called")) does not join.
  - *Trade name (masked by default):* the 1-4 distinctive words before a strong sector word (`nakliyat`, `nakliye`, `nakliyeci`, `nakliyecilik`, `lojistik`, `taşımacılık`: freight/haulage/logistics/transport; also their suffixed forms with or without an apostrophe: `Nakliyat'a`, `Nakliyattan`, `Lojistiği`; the abbreviation `Nak.`) or a legal form (`Ltd. Şti.`, `Ltd.Şti.`, `A.Ş.`, `San. Tic.`, `Limited`; in any upper/lower-case spelling: `ltd şti`, `a.ş.`) become a single `[firma]` ("company") mask **without needing a listing marker** (`Soyad Nakliyat'a yük verdim` ("I gave the load to Surname Freight") → `[firma] Nakliyat'a yük verdim`; `ve` ("and"), `&`, `Kardeşler` ("Brothers"), `Oğulları` ("Sons of") may be in between; a hyphenated name is a single name: `Ad-Soyad Nakliyat Ltd. Şti.` → `[firma] Nakliyat Ltd. Şti.`; a name joined to the sector word with a hyphen is also masked, the hyphen stays: `Soyad-Nakliyat` → `[firma]-Nakliyat`, `SOYAD-LOJİSTİK LTD. ŞTİ.` → `[firma]-LOJİSTİK LTD. ŞTİ.`; a hyphen is every form used as a phone separator: Unicode hyphen, figure/en/em dash, horizontal bar, minus sign, small and full-width hyphen; including a glued participant label: `Ad Kişi N Nakliyat` → a single `[firma]`); the sector word and the legal form stay readable (`[firma] LOJİSTİK SAN. TİC. LTD. ŞTİ.`). A **lower-case** name built with only a strong sector word needs a listing marker (it cannot be safely told apart from lower-case ordinary talk). Weak triggers (`transport`, `trans`, `kargo` (cargo), `taşıma` (carrying), `şirketi` (its company), `firması` (its firm), `logistics`) build a company only in a message with a listing marker: `Elektrik Şirketi aradı` ("The Electric Company called"), `Annem Kargo'dan aldı` ("My mother got it from the cargo company"), `HTTP Transport ayarı` ("HTTP Transport setting"), `Deploy Pipeline Transport` stay as they are. There are only three exclusions: (a) a short, documented list of generic qualifiers (`wa2md._FIRM_STOP`: `şehirler arası` (intercity), `fiyatlı` (priced), `güvenilir` (reliable), `ekonomik` (economical), `proje` (project), `ürün` (product), `satın alma` (purchasing), `festival`, `kermes` (fair), `mahalle` (neighbourhood) …: `Festival Lojistiği`, `Kermes Nakliyesi`, `Mahalle Nakliyecisi` stay) and the listing vocabulary (`uygun` (suitable), `evden eve` (home to home), `tır` (lorry) …); these words are transparent in the chain, the name before them is still masked: `Uygun Soyad Taşımacılık` → `Uygun [firma] Taşımacılık`), (b) the place list (a name built only from a place name stays: `Konya Nakliyat`, `ADANA NAKLİYAT`; a place after a name is in the surname position: `Ad Bozova Nakliyat` → `[firma] Nakliyat`), (c) a form-of-address phrase after a plural or address adjective (`değerli` (dear), `sayın`, `kıymetli` (valued), `sevgili` (beloved)…) (`Değerli Abilerim Nakliye` ("Dear Brothers Freight"), `Değerli Dayım Nakliye` ("Dear Uncle Freight")); a bare and singular possessive form of address can be a company name (`ABLA NAKLİYAT`, `DAYIM NAKLİYAT`, `Hocam Nakliyat sordu` ("Teacher Freight asked") → `[firma] …`); a singular possessive form of address before a lower-case sector word is a company name only in a message with a listing marker (`Dayım nakliyat işine girdi` ("My uncle went into the freight business") stays). A possessive-suffixed sector word also builds a trade name (`Soyad Lojistiği ödeme yapmadı` ("Surname Logistics did not pay") → `[firma] Lojistiği …`, `Soyad Lojistik ekibi` ("Surname Logistics team") → `[firma] Lojistik ekibi`). In a domain name that carries only a weak sector word (`transport`), without a listing marker only the label that carries that word is masked (`transport.example.com` stays). When a legal form is present, the words of (a) and (b) are distinctive too (`Ekspres Lojistik A.Ş.` ("Express Logistics"), `Konya Lojistik A.Ş.` → `[firma] Lojistik A.Ş.`; except grammar words: `Dün [firma] Lojistik A.Ş.`). `Şehirler Arası Nakliyat`, `Uygun Fiyatlı Taşımacılık`, `Güvenilir Nakliye Hizmeti`, `Proje Lojistiği` stay as they are. A name made only of labels stays a label (`Kişi N Nakliyat`).
  - *Domain name and link:* a narrow rule for a bare business domain name: only commercial extensions (`.com`, `.net`, `.biz`, `.info`, `.tr`, `.com.tr`, `.web.tr`…; not `.org`/`.gov`/`.edu`/`.org.tr`), case-insensitive; only the registered name and the subdomain right above it are looked at (`www` does not count). If one of them contains `nakliyat`, `nakliye`, `nakliyeci(lik)`, `lojistik`, `taşımacılık`, `transport`, `logistic(s)`, the distinctive label(s) become `[firma]`: `www.[firma].com.tr` (`soyadnakliyat`), `nakliyat.[firma].com.tr`, `www.[firma].nakliyat.com`, `[firma].COM`. A generic word that only has a suffix left once the sector word is removed (`transportation.com`, `www.nakliyat.com`) is not a company. Generic `kargo`/`trans`, words in the path and platform domain names without a sector word (`www.ornekpazar.com`, `ornekbulut.tr`) are out of scope; links in a software chat (GitHub, documentation, the product's own domain names) stay readable. If the distinctive label is a subdomain of a generic sector domain name, it is masked too (`ad.panel.nakliyat.com` → `[firma].panel.nakliyat.com`). The path, query and fragment of a link whose main host is masked (a participant label, `[firma]` or the chat label) also become `[yol]` ("path"): `https://www.Kişi N.com/[yol]`, `www.[firma].com.tr/[yol]`; a balanced closing parenthesis in the path stays inside `[yol]`, only the sentence's own (unpaired) closing parenthesis stays after it (`(bkz. https://[firma].com/[yol])` ("see")).
  - *Place name on a route (the only exception to the second principle):* a part of the participant's displayed name stays exposed only when three conditions are proven together: (1) the part is only a place name in the place list (`adlar/tr-yerler.txt`), not in the name or surname dictionary (for example a district name such as `… Bozova 2`); (2) a route or loading context: the other end is a place with an arrow or hyphen (`Şanlıurfa ➡️ Bozova`, `Akçakale ➡️Bozova`, `Bozova - Konya`), the other end is a place in the `'dan … 'a` pattern ("from … to …": `Konya'dan Bozova'ya`), or a loading word after it that a person cannot be the subject of (`Bozova yüklemeli`, `… çıkışlı`, `yüklemesi`, `yüklenecek`, `boşaltmalı`, `indirmeli`, `varışlı` (with loading, departing from, its loading, to be loaded, with unloading, with unloading, arriving at)); (3) there is no phone or contact word next to it. Everywhere else the part is masked (`Bozova aradı` ("Bozova called"), `Bozova teslim etti` ("Bozova delivered"), `Bozova - Tel: 0500…`, `Şanlıurfa ➡️ Bozova 0500…`, `Bozova - Soyad`); `teslim`, `çıkış`, `yükleme`, `indirme`, `boşaltma`, `varış` (delivery, departure, loading, unloading, emptying, arrival) are not loading words (`Bozova indirme yaptı` ("Bozova did the unloading") is a person, masked). A part that is not in the place list (`Şanlıurfa ➡️ Soyad`, `Soyad - Tel: 0500…`) is masked in every context.
  - *Protected (listing vocabulary):* the 81 province names (from the place list), big logistics districts, country/region names, vehicle and trailer types (`tır`, `kamyon`, `kırkayak`, `onteker`, `lowbed`, `tenteli`, `damper`, `frigo`… (lorry, truck, "centipede" truck, ten-wheeler, tarpaulin-covered, tipper, refrigerated)), units and common listing words (`acil` (urgent), `yük` (load), `araç` (vehicle), `fiyat` (price), `çıkışlı` (departing from)…) are never taken as a person or company name; the route (`ADANA - MERSİN`, `Adana'dan Mersin'e`, `Konya çıkışlı`), load, tonnage, price, date, time and measure (`45.000 TL`, `26 ton`, `13.60`, `15.11.2026`, `08:30`, `10 teker`, `2+1`) stay as they are. A part of a participant name that consists of these words (`… Teker`, `Tır …`, `… Konya`) is masked everywhere as in the previous version (`10 teker` → `10 Kişi N`; over-masking is accepted); a place part stays exposed only on the proven route above (`Konya çıkışlı kırkayak`).
- **End-of-run summary** (console, numbers only): masked occurrences per category (`sender`, `system line`, `extra name`, `dictionary`, `honorific`, `mention`, `contact`, `company` (trade name and domain name; `[yol]` is not counted separately), `chat name`, `phone`, `e-mail`, `username`, `iban`, `national id`, `plate`, `password`, `code`, `place/institution unclear`; with `--lang tr` the Turkish category names `gönderen`, `sistem satırı`, `ek ad`, `sözlük`, `hitap`, `anma`, `iletişim`, `firma`, `sohbet adı`, `telefon`, `e-posta`, `kullanıcı adı`, `iban`, `tckn`, `plaka`, `parola`, `kod`, `yer/kurum belirsiz`) and the **suspect remaining** count. The suspect-remaining words (words left unmasked that could be names: names that are also ordinary words, unknown words before a form of address at the start of a sentence) are written **outside the output folder**, to the user state folder: Linux `~/.local/state/wa2md/inceleme/<time>-<digest>/Sohbet-N-supheli-adlar.txt` (under `$XDG_STATE_HOME` if it is set), Windows `%LOCALAPPDATA%\wa2md\inceleme\…`, macOS `~/Library/Application Support/wa2md/inceleme/…` (`inceleme` = "review"; `supheli-adlar` = "suspect names"); the full path is written at the end of the run. Use `--review-dir FOLDER` for another place; the inside of a git work tree is not accepted, and neither is a symbolic link that points into a repository (the real path is checked; an error, exit code 2; older versions wrote `_inceleme/` next to the output, and the repository still ignores that folder name). If the review folder cannot be created or written, the run stops with a clear message and exit code 2 **without writing any output**. `wa_web.py import` / `export` use the same options (`--extra-names`, `--review-dir`, `--no-dictionary`) and the same pre-check. The file has the word, the number of occurrences, the reason and at most 3 short contexts; the things to look at first (capitalized, with a form of address) are at the top. The contexts are taken from the text **after masking**: the file only shows what already stands as it is in the output text, it does not show a masked name. Even so, since it flags which word could be a name, **do not share it, do not commit it**. **The review file is a help, not a guarantee:** it only lists remaining words that could be names and cannot catch the classes listed under "What this tool does not find automatically" below. Read the entire output before you share it; use the list to find real names that you then pass with `--extra-names` before running again.
- If a media file name contains a participant/dictionary name, the chat name or a phone (phone export), it is renamed to `medya-N.extension` (`medya` = "media"); missing attachments that are mentioned in the chat but not in the export get the same rule (`_(dosya eksik: medya-N.pdf)_`). The password/code detector is not applied to file names and attachment titles; the attachment name therefore does not change. A line counts as an attachment title / file name only in this case: the attachment's own file name itself, or a line that does not contain `:`/`=`, ends with a known file extension and is one of: a name of at least two words made only of lower-case ordinary words (`şifre listesi.pdf` ("password list"), `parola politikası.docx` ("password policy"): a title both in an attached message and as a message on its own); in an attached message a single-word name (the original name of the document, `Teklif_2024.pdf` ("Offer")) or a name that contains no password keyword. In a message that is not attached, a single-word file name (`Kartal.zip`) and a name with keyword + digit/capital/symbol (`şifre Kartal2024.docx`) do not count as a title: the password rules apply (`şifre [parola]`; the single word after a line or message with a keyword and the short password-like message in the ±3 neighbours become `[parola]`, so a message such as `rapor.pdf` ("report") next to a password conversation can also be masked). In an attached message too, the single word after a line with a keyword becomes `[parola]`; the single-word title of an attached message that has a keyword message among its ±3 neighbours also becomes `[parola]` if its stem (without the extension) looks like a password (the title `Zorlu61.pdf` of the attachment `R2.pdf` after a `şifre` ("password") message → `[parola]`); the attachment's own file name and an ordinary lower-case name like `fatura.pdf` ("invoice") do not change. So a title that contains a name (`Ad_Soyad.pdf`) next to a password conversation can also become `[parola]`. A lower-case single-word password is already not masked (`şifre kartal`); its form with an extension (`şifre kartal.zip`) also counts as a file name. In explanatory lines such as `PDF şifresi: …` ("PDF password") the password still becomes `[parola]`. On the Web path the names are already date + id.
- There is **no way** to print the real name ↔ label relation, to give it to a file or to the console (there is no mapping flag/file). The console also has no input/chat name and no message content: errors are reported with `input N` and numbers; if a detailed diagnosis is needed, only the user runs with `--no-anonymize` (not anonymized, normal output). The output files contain no real name, no mapping and no name digest (hash).
- If you want to see who is who, look at the original chat or at the `--no-anonymize` output; since the labels are positional they cannot be decoded from the output.

**Attachments:** in anonymized mode only **images, video and audio** are copied by default (an allow list). Everything else is **not copied**: contact cards (`.vcf`), PDF, office documents (`.docx`, `.xlsx`, `.pptx`, `.odt`, `.csv`, `.txt` …), archives (`.zip`, `.rar`, `.7z` …) and unknown types (`.docm`, `.xlsm`, `.eml`, `.ics`, `.html`, `.json`, `.md`, `.gpx`, `.tif`, a file without an extension: type "other"). In the Markdown, `_(ek kopyalanmadı: name, type)_` ("attachment not copied") is written in their place; to copy them use `--copy-documents` (their content is not anonymized). What every attachment is is listed in `Sohbet-N/ekler.md` (`ekler` = "attachments"; anonymous name, type, status: copied / not copied / missing) and a single warning line appears on the console: `WARNING: attachments: N copied, manual check needed (görüntü …); M not copied (PDF …)` (`görüntü` = "image"). In `--no-anonymize` mode every attachment is copied as before.

**Photos are not anonymized** (faces, screenshots and documents are copied as they are; they are listed as "manual check needed"). Copying media stays the default, also in anonymous mode; every anonymized run prints one console warning line with the number of files copied (count and advice only, no chat content). If you will share the output, use `--no-media` (in `wa2md.py` and in the `wa_web.py` commands `import`/`export`/`snippet`): media is not copied, and `_(medya dahil edilmemiş)_` ("media not included") is written instead.

**Legal note:** the default mode is "removal of direct identifiers". In the sense of the Turkish KVKK (Personal Data Protection Law), the result does not count as anonymous while content that identifies people remains in the text/photos, or while the original chat (phone, WhatsApp account, raw bundles) exists. Since the mapping is kept nowhere, the output is not "pseudonymized" but text with its direct identifiers removed. Other jurisdictions are not assessed here.

Joined or ASCII-written name forms (`AdSoyad`, `ad.soyad`, `soyad_ad`, c/g/i/o/s/u instead of ç/ğ/ı/ö/ş/ü) and the usernames, URL parts and file names that contain them are also masked (a surname and a first name that are not ambiguous also separately, as whole words; in names with three or more parts every consecutive pair/triple too; with spaces, every pair/triple selection that keeps the order of the parts too: for `Volkan Eda Su`, `Eda Su`, `Volkan Su`, `Volkan Eda` → the same `Kişi N`, with their suffixed forms (`Eda Su'ya`). A short part (2-3 letters) is masked only next to another part of the same participant; words such as `su` ("water"), `er`, `ok`, `ay` ("moon") on their own are not touched, and a short middle part on its own does not get the participant's label. If such a selection is shared by two participants it becomes `Kişi ?`; if it is another participant's full name, that one wins. A dictionary name in front is not merged with this form of the participant: `Zeynep Volkan Su` → two separate labels). Every non-first name part (at least 4 letters; in three-part names the middle part included) is a surname candidate. A first name/surname is also found with a closed suffix list (`güçlücüm`, `Kayaya`, `kayalar`; at least 4 letters) without an apostrophe; a first name/surname that is shared by several participants and has no single-word owner is masked with `Kişi ?` without knowing which one it is (so that the name cannot be read); if there is a single-word participant name, that one wins. If name + suffix equals a common word (for example `Dilek` → `dilekler`), that word is masked too.

Password-like values are also masked (`[parola]` ("password"), one-time codes `[kod]` ("code")): the value after a keyword such as `şifre/parola/pin/token/api key` (also `password`, `passwd`, `pwd`), a short password-like message in the ±3 neighbours of a message with a keyword, known secret formats (`ghp_…`, `sk-…`, JWT, long hex/base64, `Bearer …`) and long words that look random. The keyword itself stays readable. WhatsApp's own media name format (`IMG-/VID-/PTT-/DOC-/STK-/AUD-YYYYMMDD-WAnnnn[.extension]`) is never taken as a password by any rule. This is **heuristic**: some values may escape or be masked wrongly; every password/key that was shared in a chat should still be **rotated**. 40-character git digests are masked, short 7–12-character digests are not.

**What this tool does not find automatically (it does not guarantee anonymity):** a name that is not in the dictionary and stands alone on a line, with no contact word or phone next to it (`TAVRO`); in a message without a listing marker, a name next to a contact word without a delimiter (`irtibat First Last`, `FIRST LAST İRTİBAT`: only a dictionary name is masked; in a message with a listing marker it is masked only at that place, its occurrence in other messages remains); an unknown surname after a dictionary name on a line without context (`Dün First Last geldi` ("First Last came yesterday") → `Dün Kişi N Last geldi`); the lower-case or single-part occurrences of a weakly evidenced signature and of a contact name none of whose parts is in the name dictionary or a participant name (`first last geldi`, `Last geldi`: only the full phrase spreads in its capitalized form; a single part next to a form of address or `Sayın` is masked) and the lower-case occurrence of a part not in the dictionary of a contact name with a dictionary first name (`soyad dedi` ("surname said")); a contact name ending in a unit word (`İrtibat: Soyad Birimi` is not taken as a person); a name after a channel label that follows the phone and none of whose parts is in the name dictionary (`0500… Ofis: Soyad`); a name split by a zero-width character and some of the names glued to another word with this character (as in the previous version); in a message without a listing marker, a lower-case trade name (`soyad nakliyat aradı` ("surname freight called")) and a name built only with a weak trigger (`Soyad Kargo aradı`); a trade name built only on a place name or a generic qualifier (`Konya Nakliyat`, `DOĞU NAKLİYAT` ("East Freight"): it cannot be told apart from a route and from a generic expression); the distinctive word of a trade name when it occurs elsewhere without the sector word; phones written with superscript, subscript and circled digits (`⁰⁵⁰⁰`, `⓪⑤⓪⓪`); a foreign number without a separator (`004915100000000`); an extra digit group after a complete number (`0500 000 00 00 00` → `[telefon] 00`); nicknames, pet names and invented words; names that are not in the dictionary and carry no form-of-address/suffix/surname/`@`/`Sayın` hint; surnames that appear alone (`Karakoç aradı` ("Karakoç called")); names in underscore file names written in the message text (`Ad_Soyad_CV.pdf gönderdim` ("I sent")); dictionary-meaning names written in lower case or at the start of a sentence (they are only counted and written to the review file); usernames that do not look like a name; everything inside images (faces, screenshots, plates, documents) and the content of copied attachments. Exact timestamps, places and writing style can still identify people. False positives also occur: a generic word before a unit word is taken as a company (`Yazılım Lojistik ekibi` ("Software Logistics team"), `Gönüllü Lojistik ekibi` ("Volunteer Logistics team") → `[firma] Lojistik ekibi`); a generic e-mail provider domain name that has a subdomain with a sector word is taken as a company (`nakliyat.gmail.com` → `nakliyat.[firma].com`; the tool keeps no list of generic main hosts); dictionary names that have no ordinary-word meaning are masked everywhere, even if they are also a province or product name (`Aydın'dan Mersin'e` ("from Aydın to Mersin") → `Kişi N'dan Mersin'e`, `CEYHAN KUM 🧱 VAR` ("Ceyhan sand available") → `Kişi N 🧱 VAR`; the previous version masks them this way too and, by the second principle, they are not unmasked); the listing-word part of a participant name is masked everywhere; a news-site domain name that carries a sector word also becomes `[firma]` (`www.[firma].com/[yol]`); in a message with a listing marker, two unknown words next to a contact word, or a word that is a surname in the list, are taken as a name (`Tel Aviv Seferi` ("Tel Aviv trip"), `Hayırlı İşler İrtibat` ("Good luck, contact")); a capitalized word with a meaning that is a name in the middle of a sentence (`… olmalı Temel bir logo` ("… should be a basic logo")) is taken as a name. If your own name is an ordinary word such as "Ben" ("I"), that word in the text is masked too.

## Running blind for an AI agent

Aim: an AI agent runs the script on real exports without learning who is who.

1. Put the phone-export zips in an **input folder** chosen by the owner. The agent is given only the path of this folder; the agent does not list or open the folder (file names contain person names).
2. The agent runs only this one command; a new **output folder** is used on every run, because the `Sohbet-N` labels are positional:

   ```
   python wa2md.py <input-folder> --out <output-folder>/<YYYYMMDD-HHMM>
   ```

   It works on Windows, Linux and macOS; **Python 3.9 or later** and only the standard library are enough (the 3.9 lower bound comes from `argparse.BooleanOptionalAction`; the script parses as syntax on 3.8 too, but the `--anonymize`/`--anonim` flag needs 3.9). No venv/Playwright is **needed** for `wa2md.py`; only the experimental `list`/`export` of the WhatsApp Web path and the browser tests need Playwright. Since the output labels contain Turkish characters, the script forces stdout/stderr to UTF-8 (it does not crash on an ASCII console either).

3. What the agent sees: on the console only labels and numbers (summary counts included) (`[Sohbet-1] N messages, M media ... -> path`, failed inputs as `input N`; no name, zip/file name, phone, message text or unparsable lines are printed), then only the anonymous Markdown in the `Sohbet-N` folders. The review file (written outside the output folder, in the user state folder, see "End-of-run summary") contains possible real names: the agent does not open it, only you look.
4. `--no-anonymize` is **for you only** (it produces non-anonymized normal output with real names and detailed error diagnosis); it is not given to the agent. In anonymized mode there is no flag that shows or stores the mapping.

Limit: this protects only the console and the output files. Photos are not anonymized (the agent must not carry a name over from an image); `wa_web.py list` prints chat names, and the agent must not run it.

## Output format

Day heading `## YYYY-MM-DD`, message `**Name** HH:MM`, photo `![](media/file.jpg)`, other files as links, system notes in italics, quoted reply as a `> ` line. On the Web path the media name is `<YYYYMMDD-HHMM>-<short message id>[-n].<extension>`.

## Tests

```
python -m unittest discover -s tests -v
.venv\Scripts\python -m unittest discover -s tests -v
```

The second (venv) also runs the real-Chrome tests: it runs `wa_collect.js` in a real (headless) Chrome on invented fixtures that imitate the real WhatsApp Web DOM structure; it also starts its own temporary Chrome with a separate profile and tries the CDP `list`/`export` flow on a fake WhatsApp page. It does not touch your Chrome. If there is no venv/Chrome those tests are skipped.

## Privacy

`exports/`, `out/`, `*.zip`, `wa-bundle-*.json` and `.venv/` are listed in `.gitignore`. That lowers the risk of committing chat data but does not remove it: other folders and file names are not covered, and `git add -f` overrides it. Check `git status` and the contents before every commit and push. The test data and fixtures are synthetic (see "Data sources and attribution").
